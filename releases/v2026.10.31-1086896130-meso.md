## Docker and provider

- **Docker startup keeps the saved proxy config when an import fails** **[redeploy]** (2326c8c8, ff69bf59, 6f1d7687, a4e57efe, 56104b33, 2567b218). The echoed address is trimmed before redaction matching, and the staging sweep spares a live directory. Staged imports stay away from live state. Corrupt saved state is kept for recovery and no longer blocks startup. Startup stops only when no usable config is saved.
- **Docker debug logs redact credentials; nightly starts reuse the stored JWT** **[redeploy]** (32489225, 1662af74, c5aa058a, 47785a9b, b92662ab).
- **Provider proxy state changes hold the proxy lock** **[redeploy]** (5a93487d, 1510520d, d01c7df6, 921b9999). An unreadable `proxy.state` is reported, not masked, and a file proxy add keeps the source file's owner and mode.
- **Provider logs redact malformed addresses and raw keys** **[redeploy]** (1e915804).
- **Shutdown no longer waits behind a queued reload** **[redeploy]** (b98aa755).
- **A changed preset API URL triggers the stale JWT warning** **[redeploy]** (96a61b1e).
- **The extender DNS forwarder frees a source's in-flight slot before it writes the answer** **[redeploy]** (`extender/extender_dns.go`). A client that answered and asked again quickly was refused as "already has a query in flight". The slot is released before the write, and the deferred release still covers early returns.
- **The degraded reaper's log says which of its two holds applies** **[redeploy]** (f9057cee, b7ebef77). The held-off line now distinguishes a recent backend outage from a degraded set with no ranking to cull by, and the resume line confirms both have cleared.
- **The RAM-log trim does not hold the writer lock during the copy** **[redeploy]** (9b7ea765, 6e84da18, a5b5249b).
- **The URL fetch failure reason stays in the important log** **[redeploy]** (a48c7ca7, bbc48004).
- **The persisted `smart_dialer` preference is applied once at start, in both directions** **[redeploy]** (7b01ef21). An unset key puts the flag at off instead of leaving whatever an earlier replay set. The key stays restart-required.
- **Unreadable RAM is classified by its source for the headroom cap** **[redeploy]** (25a7ad8d).
- **The OOM-cap persist-failure path has a regression test** **[no redeploy]** (dac1de3d). No behaviour change.
- **The Docker updater takes the version from the release tag** **[redeploy]** (a1357a54, tests 946fd6ef, 9cceb57b).
- **The Pelican panel script accepts `URNETWORK_AUTH_CODE`** **[redeploy]** (ab616493).
- **Proxy-list fetches report progress while they run** **[redeploy]** (62aac416, #69). A large public list used to be minutes of silence between "fetching now" and the summary. Each step is announced, a heartbeat every 30 seconds gives an honest remaining estimate, and the source being downloaded is named.
- **IPv6 failures are remembered per proxy carrier** **[redeploy]** (f3604b29, #66; 38efd42a, #71). A SOCKS exit without IPv6 only shows it by letting a v6 dial hang. After three consecutive explicit v6 failures through one carrier, v6 is refused through that carrier for 15 minutes, then one probe is let through. Carriers do not affect each other or the host. A streak is bound to ten minutes, so old failures cannot add up to a suppression.

## urnet-tools and installers

- **The workstation flag is removed from `urnet-tools`** **[redeploy]** (49a31d42, 6c90f970, 7cc5bdca). Signing has no gate, and seed use asks a person or refuses. A script that still passes `--i-am-on-my-own-workstation` gets a warning naming the removed flag, and the command carries on. A box that also runs a provider gets a warning that says why the combination is a bad idea.
- **Both help menus now show the support mailbox and the community Discord** **[redeploy]** (c51fffe5, 11589dd4). `urnet-tools --help` and `urnet-docker --help` end with `Need help? Email support@fullbars.xyz, join https://discord.gg/urnetwork, or visit https://github.com/urfoundation/meso-miner`.
- **The FreeBSD installer refuses an asset whose digest cannot be established** **[installer]** (a1d5dcb1).
- **FreeBSD provider discovery and cron use the root-owned copy** **[redeploy] [installer]** (cffea783, 36ac726c, 03b529c0, e09861b2).
- **The FreeBSD installer never writes through a symlinked shell rc** **[installer]** (69006d0a).
- **The FreeBSD installer replaces its version file instead of following it, and accepts a staged binary that only lost its exec bit** **[installer]** (35a0de93, 2f4d0cb4).
- **`urnet-tools` on macOS takes the darwin path from the universal tarball; `logs --important` follows rotation** **[redeploy]** (b556feb1, 14f79bc6).
- **The Linux installer fails closed when release metadata is unreadable, keeps the live binary when the backup fails, reports a failed rollback accurately, and writes the version marker only after the units start** **[installer]** (e227adf1, 4b8c8d2f, f6db7343, d4d9b852).
- **The FreeBSD installer backs up the provider binary and rolls it back; a failed exit removes the backup; `urnet-tools update` keeps the install tree root-owned** **[installer]** (a1420f86, 38e327c9, 2c9782bb).
- **The FreeBSD installer keeps the old tool when the provider backup fails** **[installer]** (eb0ea1d7, #68). The new `urnet-tools` is installed only after the backup succeeds, so a failed backup no longer leaves the new tool beside the old provider. The backup is cleared only when its removal worked, so a failed `rm` is retried at exit.

## Security

- **The CFAA and IP blocker tables refreshed** **[redeploy]** (6e7a6875, 8004c71f). Data only; it takes effect once a node runs this release.
- **The h3 relay dial error no longer carries proxy credentials into the operator log** **[redeploy]** (1559e7bf, #68). The dial error was wrapped with `%w`, and a net error echoes the address it was given, so userinfo and the token path reached the log past the redaction. The provider now returns the context error or a short failure class, and tests pin both.

## Repository sync

- **This tree is level with `full-bars/meso-miner`** **[no redeploy]** (#67). The fork's main line is merged in, so the provider and miner code, the pages and the test files match in both repositories. Only repository identity differs: the download URLs, the help text and the release-repo guards.
- **`transfer.proto` now matches its generated code** **[no redeploy]** (46d1dcc9). The source had been left declaring field 6 as "not ported, do not reuse" while the committed `transfer.pb.go` already carried `ip_family`, `client_info`, `stream_lease_version` and `expiration_time_unix_milli`. Regenerating from that source produced a `pb.go` with none of the four, which would have silently changed the auth frame and contract signing on the next `make`.
- **The redaction and FreeBSD digest tests are back under test** **[no redeploy]** (38b2cb6d). Four FreeBSD installer digest cases and the two error-redaction cases were restored with the harness that loads the shipped digest helpers, not stubs.

- **The docs name the metrics port as 9100** **[no redeploy]** (6bd2b975). The code listens on 9100 and falls back to 9101 to 9103; three pages still said 9091.
- **vnStat is described as retired everywhere** **[no redeploy]** (3df1e37c, #72). The config table, deployment guide, scaling guide, README pointer and Pelican page no longer tell operators to enable it or map port 8080. The heading is kept so linked anchors resolve, and the shakedown probe now fails when the retired port answers.
- **The redaction test pins the relay-dial branch** **[no redeploy]** (514a3b60, #70). The UDP check can reject before the dial, so the test could pass without reaching the dial. It now stubs the check to fall through and requires the relay-dial message.
- **The FreeBSD root-shell install names a service account; the container command pages match what the image runs; the extender row matches the build** **[no redeploy]** (86d1f3c2). The FreeBSD beginner guide's root-shell path now sets `SERVICE_USER_OVERRIDE`, because the installer refuses to run the service as root. The container's `urnet-tools` is a shell wrapper that does not implement `metrics`, `rename`, `direct`, `usage` or `sn-status`, and `urnet-docker` forwards those to it, so the docs no longer present them as working inside the container. Metrics are on by default in the container, so the `metrics on` exec step is removed. The extender configuration row says the role binds its listeners but serves no traffic in this build.

## Deploy notes

1. Docker: nodes on the stable or nightly images pick up the startup proxy-import safety, the credential redaction and the version-from-tag updater only after the image is redeployed.
2. FreeBSD and Linux hosts: re-run the installer (or `urnet-tools update`) to get the digest check, the root-owned discovery path and the backup/rollback behaviour.
3. `urnet-tools wallet` no longer accepts `--i-am-on-my-own-workstation`; scripts that pass it get a warning naming the removed flag and the command carries on.
