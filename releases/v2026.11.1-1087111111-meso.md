- **The provider remembers IPv6 failures per proxy carrier** **[redeploy]** (f3604b29, #66; 38efd42a, #71). A SOCKS exit without IPv6 only shows it when a v6 dial hangs. After three explicit v6 failures in a row through one carrier, the provider refuses explicit v6 dials through it for 15 minutes. The dial falls back to v4 at once. When the 15 minutes end, one probe dial goes through. Success clears the verdict. Failure starts another 15 minutes. A carrier never affects another carrier or the host. A gap of more than 10 minutes between two failures resets the streak, so old failures cannot add up to a refusal. The whole streak can span longer than 10 minutes. Only dials that name v6 count, by network or address. The provider cannot tell the exit's family when it passes a hostname to the proxy. The default `proxy_target_family=v4` mode never shows the family, so it does not trigger this.

## Metrics endpoint

This is not a new change. The pages were wrong, so read this once.

- The provider starts `/metrics` by itself. No setting is needed.
- On a bare-metal host or VM, it listens on `127.0.0.1` and on any Tailscale IPv4 address.
- In a Docker container on a bridge network, it listens on `0.0.0.0` inside the container. Other containers and hosts with a route to it can reach it even without a published port.
- In a container that shares a publicly addressed network, such as `--network host`, it stays on loopback and Tailscale and logs a notice. Set `URNETWORK_METRICS=<ip:port>` to choose another address.
- `auto` is the default. It tries ports 9100, 9101, 9102 and 9103, and takes the first free one.
- `urnet-tools metrics status` prints the address in use.
- `URNETWORK_METRICS=<ip:port>` pins one exact address. It beats every other setting.
- `urnet-tools metrics off` stops the endpoint. To keep it off across restarts and HotSwap, also remove `URNETWORK_METRICS`: a nonempty value starts it again. `urnet-tools metrics listen auto` goes back to the default.
- Port 9091 does not exist.

> [!NOTE]
> Do not set `URNETWORK_METRICS=off`. The provider reads any value as an address and fails to bind it. The log shows `listener failed`, and the default listener does not start. Run `urnet-tools metrics off` instead, and leave `URNETWORK_METRICS` unset.

## Security

- **The CFAA and IP blocklists are synced with the sibling forks** **[redeploy]** (6e7a6875, 8004c71f). Before, this repo blocked a different set of destinations. The change is data only (`ip_blocker_block.go`, `ip_security_cfaa_block.go`). It takes effect once a node runs this release.
- **The h3 relay dial error no longer carries proxy credentials into the operator log** **[redeploy]** (1559e7bf, #68). The code wrapped the dial error with `%w`. A net error repeats the address it was given. So the proxy user, password and token path reached the log past the redaction. The provider now returns the context error, or a short failure class. Tests cover both.

## Deploy notes

1. Docker: nodes on the stable or nightly images pick up the startup proxy-import safety, the credential redaction and the version-from-tag updater only after the image is redeployed.
2. FreeBSD and Linux hosts: re-run the installer (or `urnet-tools update`) to get the digest check, the root-owned discovery path and the backup/rollback behaviour.
3. `urnet-tools wallet` no longer has `--i-am-on-my-own-workstation`. Scripts that pass it get a warning, and the command carries on. Remove the flag from your scripts.
